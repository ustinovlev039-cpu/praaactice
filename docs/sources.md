# Источники и редакционные принципы

## Материалы пользователя

Основной источник — предоставленный автором архив **«пт.zip»** с учебными кейсами и теорией PT Start / Positive Technologies. В портфолио вошли **23 сетевых, 13 Windows- и 14 веб-кейсов**. [Соответствие файлов](source-map.md).

Формулировки переработаны в сжатые разборы: добавлены навигация, схемы, критерии подтверждения, аналитический контекст и повторная проверка защиты. Это не официальная публикация курса. Оригинальные учебные образы, токены чекеров, ответы тестов и закрытые ссылки на загрузки не входят в публикацию.

Схемы созданы для этого портфолио. Команды служат контрольными проверками и примерами исправлений; конкретные версии и результаты прогона фиксируются в отчёте. Иллюстрации исходного курса не используются как доказательства личного выполнения.

## Официальные справочники

- [OWASP Top 10:2025](https://top10.owasp.org/2025/) — названия категорий; порядок соответствует редакции в архиве.
- [OWASP Web Security Testing Guide 4.2](https://owasp.org/www-project-web-security-testing-guide/v42/) — структура проверок безопасности веб-приложений.
- [OWASP Cheat Sheet Series](https://cheatsheetseries.owasp.org/) — рекомендации по устранению первопричин уязвимостей.
- [Microsoft Sysmon](https://learn.microsoft.com/en-us/sysinternals/downloads/sysmon) — типы событий и зависимость телеметрии от конфигурации.
- [Microsoft Windows Security Auditing](https://learn.microsoft.com/en-us/windows/security/threat-protection/auditing/security-auditing-overview) — штатный аудит Windows.
- [Suricata EVE JSON](https://docs.suricata.io/en/latest/output/eve/eve-json-output.html) — поля сетевой телеметрии и событий.
- [PT Open Rules](https://rules.ptsecurity.com/) — открытые правила сетевого обнаружения.
- [Документация MikroTik](https://help.mikrotik.com/docs/) — конфигурация RouterOS с учётом версии.
- [DefectDojo](https://docs.defectdojo.com/) — импорт и учёт находок.
- [Bandit](https://bandit.readthedocs.io/) и [Semgrep](https://semgrep.dev/docs/) — статический анализ.

## Как трактовать результаты

Сработавшая сигнатура не равна доказательству успешной эксплуатации. Отсутствие события не равно отсутствию действия. Состояние `allowed` в пассивном IDS-сценарии не является подтверждением блокировки. Для вывода соединяются запрос, сетевой поток, событие на хосте и фактическое изменение состояния.

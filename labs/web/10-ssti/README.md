# WEB-10 · SSTI и граница шаблона

> Отличить данные шаблона от пользовательского управления его исходным текстом.

| Формат | Исходный кейс | Основной фокус |
| :-- | :-- | :-- |
| Учебная практика PT Start | `904` | Web / OWASP |

**Привязка к OWASP:** A05:2025 Injection.

## Стенд и схема

Учебное приложение и компоненты соответствующего кейса PT Start. URL, параметры и пути необходимо брать из своего стенда; примеры ниже поясняют проверку или исправление.

```mermaid
flowchart LR
    n0["Ввод пользователя"]
    n1["Исходный текст шаблона"]
    n2["Шаблонизатор"]
    n3["HTML-ответ"]
    n0 --> n1 --> n2 --> n3
    classDef default fill:#10283b,stroke:#ffb467,color:#ffffff,stroke-width:2px
```

Схема показывает логику лабораторной. Для точного повторения исходного кейса используются его адресный план, образы и версии компонентов. Подготовка среды описана в [руководстве по стендам](../../../docs/lab-environment.md).

## Ход работы

1. Найти поле, которое участвует в генерации страницы учебного сервиса.
2. Проверить текстовый и арифметический маркер, учитывая синтаксис движка.
3. Сопоставить ответ с вызовом рендера и установить, контролируется ли исходный текст шаблона.
4. Перенести ввод в параметры заранее заданного шаблона.
5. Проверить, что выражение отображается как данные и штатный рендер сохранён.

## Команды и контрольные проверки

```text
Для учебного Jinja-контекста: {{ 7 * 7 }}
Сравнить: пользовательский исходный текст шаблона и пользовательское значение переменной фиксированного шаблона.
Движок и поведение установить по коду/ответу, а не угадыванием.
```

Это команды проверки или пример исправления, а не сохранённый вывод с выполненного стенда. Полный набор действий зависит от подготовленного образа и версии ПО.

## Как подтвердить результат

- Запрос, результат вычисления и место вызова рендера.
- Исправленный способ передачи данных и повторная проверка.

Для фиксации фактического прогона используется [шаблон отчёта](../../../templates/run-report.md).

## Что важно для SOC

Вывод 49 — начальный признак, а не полное доказательство RCE. Уточнить движок, контекст и доступные объекты.

## Защита и повторная проверка

Не рендерить пользовательский текст как доверенный шаблон, ограничивать доступные объекты и ресурсы.

После изменения конфигурации повторяется исходная проверка: нужно подтвердить устранение причины и сохранение штатной функции, а не только исчезновение ошибки в интерфейсе.

# WEB-01 · Burp Suite: перехват HTTP/HTTPS

> Проследить запрос через прокси и воспроизвести его с контролируемым изменением.

| Формат | Исходный кейс | Основной фокус |
| :-- | :-- | :-- |
| Учебная практика PT Start | `886` | Web / OWASP |

**Привязка к OWASP:** Методика тестирования; отдельной категории OWASP не соответствует.

## Стенд и схема

Учебное приложение и компоненты соответствующего кейса PT Start. URL, параметры и пути необходимо брать из своего стенда; примеры ниже поясняют проверку или исправление.

```mermaid
flowchart LR
    n0["Браузер"]
    n1["Burp Proxy и Repeater"]
    n2["Учебное приложение"]
    n3["Сравнение ответов"]
    n0 --> n1 --> n2 --> n3
    classDef default fill:#10283b,stroke:#ffb467,color:#ffffff,stroke-width:2px
```

Схема показывает логику лабораторной. Для точного повторения исходного кейса используются его адресный план, образы и версии компонентов. Подготовка среды описана в [руководстве по стендам](../../../docs/lab-environment.md).

## Ход работы

1. Открыть учебное приложение во встроенном браузере Burp Suite и ограничить scope адресом стенда.
2. Перехватить обычный запрос и определить метод, путь, параметры, заголовки и cookie.
3. Отправить запрос в Repeater, изменить один безопасный параметр и сравнить ответы.
4. Для HTTPS использовать доверие к сертификату Burp только в учебном профиле; сохранить запросы без токенов сессии.

## Команды и контрольные проверки

```bash
export LAB_URL=http://127.0.0.1:8000
curl -i "$LAB_URL/"
# Адрес и порт заменить на фактический локальный учебный сервис.
```

Это команды проверки или пример исправления, а не сохранённый вывод с выполненного стенда. Полный набор действий зависит от подготовленного образа и версии ПО.

## Как подтвердить результат

- Пара исходный/изменённый запрос и соответствующие ответы.
- Описание поля, которое повлияло на серверное поведение.

Для фиксации фактического прогона используется [шаблон отчёта](../../../templates/run-report.md).

## Что важно для SOC

Прокси показывает клиентскую сторону обмена. Для вывода об обработке на сервере нужны ответ и серверный журнал, а не только отправленный запрос.

## Защита и повторная проверка

Ограничивать scope и доступ к прокси; не переносить учебный CA в системное доверие основной рабочей среды.

После изменения конфигурации повторяется исходная проверка: нужно подтвердить устранение причины и сохранение штатной функции, а не только исчезновение ошибки в интерфейсе.

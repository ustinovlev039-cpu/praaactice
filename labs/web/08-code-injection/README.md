# WEB-08 · Code Injection

> Выявить выполнение пользовательского ввода как программного кода.

| Формат | Исходный кейс | Основной фокус |

**Привязка к OWASP:** A05:2025 Injection.

## Стенд и схема

Учебное приложение и компоненты соответствующего кейса PT Start. URL, параметры и пути необходимо брать из своего стенда; примеры ниже поясняют проверку или исправление.

```mermaid
flowchart LR
    n0["Недоверенный ввод"]
    n1["Динамический интерпретатор"]
    n2["Контекст приложения"]
    n3["Результат вычисления"]
    n0 --> n1 --> n2 --> n3
    classDef default fill:#10283b,stroke:#ffb467,color:#ffffff,stroke-width:2px
```

Схема показывает логику лабораторной. Для точного повторения исходного кейса используются его адресный план, образы и версии компонентов. Подготовка среды описана в [руководстве по стендам](../../../docs/lab-environment.md).

## Ход работы

1. Найти учебную функцию динамического вычисления выражения.
2. Сравнить обычный текст с выражением, имеющим безвредный вычисляемый результат.
3. Проверить, попадает ли ввод в eval/exec или аналогичный механизм.
4. Описать контекст и права выполнения отдельно от текста ответа.
5. Заменить выполнение кода парсером ограниченного формата и повторить тест.

## Команды и контрольные проверки

```text
Безопасный маркер вычисления: 7 * 7
Проверить реализацию обработчика: результат 49 сам по себе ещё не доказывает произвольное выполнение кода.
Цель исправления — ограниченный формат данных вместо выполнения переданной программы.
```

Это команды проверки или пример исправления, а не сохранённый вывод с выполненного стенда. Полный набор действий зависит от подготовленного образа и версии ПО.

## Как подтвердить результат

- Запрос и ответ, фрагмент обработчика, контекст выполнения.
- Сравнение допустимых данных и отвергаемых выражений после исправления.

Для фиксации фактического прогона используется [шаблон отчёта](../../../templates/run-report.md).

## Что важно для SOC

Не путать штатный калькулятор с произвольным исполнением. Доказательство должно включать небезопасный механизм и выход за допустимую бизнес-функцию.

## Защита и повторная проверка

Исключить eval/exec для недоверенных данных; использовать явную грамматику и ограничения ресурсов.

После изменения конфигурации повторяется исходная проверка: нужно подтвердить устранение причины и сохранение штатной функции, а не только исчезновение ошибки в интерфейсе.

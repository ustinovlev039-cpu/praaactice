# WIN-13 · Групповые политики и доверие к SYSVOL

> Централизованно применить настройки безопасности и разобрать влияние компрометации SYSVOL.

| Формат | Исходный кейс | Основной фокус |
| :-- | :-- | :-- |
| Учебная практика | `883` | Windows |

## Стенд и схема

Windows/Windows Server с нужными ролями; для доменных команд — RSAT/модуль ActiveDirectory или GroupPolicy. Повышенная консоль нужна только для административных шагов.

```mermaid
flowchart LR
    n0["Администратор GPO"]
    n1["AD / связь с OU"]
    n2["SYSVOL / файлы политики"]
    n3["Клиент и gpresult"]
    n0 --> n1 --> n2 --> n3
```

Схема показывает логику лабораторной. Для точного повторения исходного кейса используются его адресный план, образы и версии компонентов. Подготовка среды описана в [руководстве по стендам](../../../docs/lab-environment.md).

## Ход работы

1. В существующем учебном домене создать OU и разместить нужные объекты.
2. Создать и привязать GPO с парольной политикой и параметрами безопасности, учитывая область действия.
3. Проверить применение gpupdate/gpresult, отличить пользовательские и компьютерные параметры.
4. На отдельном снимке разобрать сценарий безопасного маркера через SYSVOL из кейса.
5. Удалить маркер, восстановить политики и проверить аудит изменений.

## Команды и контрольные проверки

```powershell
gpupdate /force
gpresult /r
gpresult /h C:\Labs\gpresult.html
Get-GPO -All | Select-Object DisplayName,Id,GpoStatus
```

Это команды проверки или пример исправления, а не сохранённый вывод с выполненного стенда. Полный набор действий зависит от подготовленного образа и версии ПО.

## Как подтвердить результат

- Связь OU—GPO и отчёт результирующей политики.
- Проверка применения и доступных событий изменения AD/SYSVOL.

Для фиксации фактического прогона используется [шаблон отчёта](../../../templates/run-report.md).

## Что важно для SOC

5136/5137 относятся к изменениям объектов каталога при подходящем аудите и SACL. Изменение файла в SYSVOL требует отдельного файлового аудита; эти источники не взаимозаменяемы.

## Защита и повторная проверка

Ограничить право редактирования GPO и SYSVOL, разделить администрирование по уровням и контролировать скрипты запуска.

После изменения конфигурации повторяется исходная проверка: нужно подтвердить устранение причины и сохранение штатной функции, а не только исчезновение ошибки в интерфейсе.

# NET-12 · DHCP Starvation и Rogue DHCP

> Связать исчерпание адресного пула с появлением поддельных DHCP-параметров.

| Формат | Исходный кейс | Основной фокус |
| :-- | :-- | :-- |
| Учебная практика | `819` | Сети |

## Стенд и схема

Debian и сетевые ВМ по схеме кейса. Адреса и имена интерфейсов в командах — примеры, их нужно сверить с фактической схемой.

```mermaid
flowchart LR
    n0["Учебный генератор"]
    n1["DHCP MikroTik и rogue DHCP"]
    n2["Клиент / ложный шлюз"]
    n0 --> n1 --> n2
```

Схема показывает логику лабораторной. Для точного повторения исходного кейса используются его адресный план, образы и версии компонентов. Подготовка среды описана в [руководстве по стендам](../../../docs/lab-environment.md).

## Ход работы

1. Снять снимок изолированного стенда и сохранить исходные аренды MikroTik.
2. Воспроизвести учебный сценарий исчерпания пула и отметить изменение числа аренд.
3. Включить тестовый rogue DHCP в этой же внутренней сети.
4. Сравнить Offer/ACK от доверенного и поддельного серверов; восстановить доверенную выдачу параметров.

## Команды и контрольные проверки

```routeros
/ip dhcp-server lease print
/ip dhcp-server network print
/log print where topics~"dhcp"
```

Это команды проверки или пример исправления, а не сохранённый вывод с выполненного стенда. Полный набор действий зависит от подготовленного образа и версии ПО.

## Как подтвердить результат

- Состояние пула и число аренд до и после.
- PCAP с DHCP server identifier, выданными gateway и DNS.

Для фиксации фактического прогона используется [шаблон отчёта](../../../templates/run-report.md).

## Что важно для SOC

Всплеск уникальных MAC, истощение пула и Offer от неизвестного сервера усиливают друг друга как признаки атаки. Проверять и обычный рост клиентов.

## Защита и повторная проверка

Использовать DHCP snooping, доверенные порты и ограничения частоты DHCP-запросов.

После изменения конфигурации повторяется исходная проверка: нужно подтвердить устранение причины и сохранение штатной функции, а не только исчезновение ошибки в интерфейсе.
